Magneton: Energy Profiler for
Machine Learning Systems

Magneton is an energy profiler that provides fine-grained, accurate energy attribution for ML applications across Python, C/C++, and GPU layers. It correlates CPU-side launches with GPU execution and attributes power and energy to kernels, operators, and user annotations.

Yi Pan, Wenbo Qian, Dedong Xie, Ruiyan Hu, Yigong Hu, Baris Kasikci
📄 Read Paper GitHub

Why Energy Profiling for ML Is Hard

Cross-layer ML applications combine Python, C/C++, and GPU execution with asynchronous scheduling—making traditional CPU-only profilers insufficient for accurate energy attribution.

🔄 Asynchronous GPU Execution

The GPU programming model decouples CPU-side launches from GPU execution, creating temporal gaps that complicate energy attribution.

🧩 Cross-Layer Context

Python, native runtimes, and GPU layers require different tracing mechanisms that must be combined into one causal execution trace.

Magneton: Cross-Layer Energy Profiling

Magneton correlates CPU calls, framework operators, and GPU activities into a unified timeline and attributes accurate energy to kernels, operators, and user annotations with low overhead.

Why It Matters

Reliable energy attribution unlocks principled optimization for ML systems—from kernel design to operator graphs and application-level choices.

Magneton makes energy a first-class metric—enabling efficient, fair, and sustainable ML deployment.

Profiling Architecture

Magneton builds a unified, causal execution trace across Python, native runtimes, and GPU execution to enable accurate energy attribution.

GPU Events Tracing

Magneton captures low-level GPU activities (kernel execution, memory copies) using the CUPTI Activity API. Activity tracing collects detailed timestamps with minimal runtime overhead by leveraging hardware counters and timeline information.

Framework & Runtime Interception

At the framework level, Magneton hooks into deep learning operators (e.g., PyTorch via TorchDynamo). Simultaneously, it intercepts CUDA runtime calls (kernel launches, allocations, transfers) using the CUPTI Callback API to connect high-level ops with low-level GPU APIs.

Call Stacks & Python Tracing

Magneton records native call stacks at kernel launch sites (via libunwind) and Python function entry/exit (via CPython PyEval_SetProfile) to provide full-context attribution from Python code to GPU execution.

Synchronization & Correlation

Using CUPTI correlation IDs, CPU-side API calls and their resulting GPU activities share the same ID, enabling a unified trace that faithfully reflects causality from CPU scheduling to GPU execution.

Energy Measurement and Attribution

NVML power readings are coarse (20–30 ms updates) and delayed, making runtime per-kernel energy inaccurate. Magneton addresses this with two complementary options: a direct power meter for precise timestamps, or offline NVML-based kernel replay (30–50 iterations) that achieves stable per-kernel estimates with < 5% error.

Direct Power Meter

When available, a power meter provides microsecond-scale, accurate GPU power readings with precise timestamps, enabling high-fidelity per-kernel energy attribution.

NVML with Kernel Replay

NVML power readings update every 20–30 ms and lag real activity, making per-kernel measurement inaccurate at runtime. Magneton mitigates this by replaying captured dataflow nodes offline (30–50 iterations) and averaging NVML readings to estimate stable per-kernel power with < 5% error per our measurements.

Design Note

Replay runs are executed offline to avoid production overhead and prevent cache pollution; profiling remains transparent to users, maintains accuracy, and requires no source changes to production code.

Profiler Outputs

What Magneton Produces

  • Per-kernel energy: energy and average power per GPU kernel
  • Operator-level attribution: energy attributed to DL operators
  • Request-level aggregation: energy per user request / pipeline stage
  • Unified timeline: correlated CPU, framework, and GPU events
  • Dataflow graph capture: nodes used for offline replay
  • Export: JSON/CSV summaries and trace for visualization
